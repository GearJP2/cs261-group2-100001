## 1. ใครถอนตัวได้

- ผู้ใช้ต้องเข้าสู่ระบบและเป็นสมาชิกปัจจุบันของ Party นั้น (`left_at IS NULL`)
- ถอนตัวได้เฉพาะตนเอง โดยอ้างผู้ใช้จาก session ไม่ให้เลือกสมาชิกคนอื่นเพื่อถอนแทน
- ผู้ที่มีคำขอ Pending หรือ Rejected แต่ยังไม่ได้เป็นสมาชิก ถอนไม่ได้ การยกเลิกคำขอเข้าร่วมเป็นคนละกรณีกับการถอนตัว
- Host ถอนตัวผ่านกระบวนการนี้ไม่ได้ ให้ใช้การยกเลิก Party ตาม US7 ซึ่งมีกฎตรวจสิทธิ์และเวลาของตัวเอง การโอน Host ไม่อยู่ในขอบเขตงานนี้

## 2. สถานะและเวลาที่อนุญาต

ตารางนี้ใช้กับสมาชิกปัจจุบันที่ไม่ใช่ Host:

| สถานะ Party | ถอนตัวครั้งแรกได้หรือไม่ | กติกา |
| --- | --- | --- |
| Open | ได้ | ต้องยังไม่ยกเลิก และเวลาปัจจุบันน้อยกว่าเวลาเริ่ม |
| Full | ได้ | ใช้กติกาเดียวกับ Open; การเต็มไม่ขัดขวางการคืนที่ว่าง |
| InProgress | ไม่ได้ | กิจกรรมเริ่มแล้ว |
| Completed | ไม่ได้ | กิจกรรมจบแล้ว |
| Cancelled | ไม่ได้ | คงข้อมูลสมาชิกไว้ ไม่ถอนหรือคืนที่ว่างเพิ่มเติม |

- อนุญาตเมื่อ `now < starts_at` เท่านั้น ที่ `now == starts_at` ถือว่าเริ่มแล้วและถอนไม่ได้ ไม่มีระยะผ่อนผัน
- ใช้เวลาของ server และเปรียบเทียบ datetime ที่มี timezone ไม่ใช้เวลาเครื่องผู้ใช้หรือเวลาที่เปิดหน้าจอยืนยัน
- ตรวจเวลาใหม่หลังได้ Party lock หากกดก่อนเริ่มแต่รอจนถึงเวลาเริ่ม ให้ปฏิเสธการถอน
- ใช้เวลาที่ตรวจผ่านหลังได้ lock เป็นเวลาถอน ไม่รับประกันว่า response จะถึงผู้ใช้ก่อนกิจกรรมเริ่ม
- หาก Party ทั้งยกเลิกและเลยเวลาเริ่ม ให้แจ้งเหตุผลว่ากิจกรรมถูกยกเลิกก่อนเหตุผลเรื่องเวลา

## 3. ผลเมื่อถอนสำเร็จ

- บันทึก `left_at` ของ membership เดิม เก็บแถวไว้ ไม่ลบประวัติสมาชิกและไม่สร้างแถวใหม่
- สมาชิกปัจจุบันนับจาก `left_at IS NULL` รวม Host; ที่ว่างเท่ากับ `capacity - จำนวนสมาชิกปัจจุบัน` ไม่เพิ่ม capacity หรือเก็บตัวนับที่ว่างอีกชุด
- การถอนหนึ่งคนลดสมาชิกปัจจุบันหนึ่งคนและคืนหนึ่งที่ว่าง หากไม่มีการเปลี่ยนแปลงอื่นพร้อมกัน Party ที่ Full จะกลับเป็น Open
- ไม่อนุมัติผู้รอเข้าร่วมอัตโนมัติ และไม่เปลี่ยนคำขอ Approved เดิมเป็น Pending หรือ Rejected จากการถอนเพียงอย่างเดียว
- ผู้ถอนกลับมาขอเข้าร่วมได้ตาม US3 แต่ต้องส่งคำขอและรอ Host อนุมัติใหม่ตาม US10 จึงกลับเป็นสมาชิกและใช้ที่ว่างอีกครั้ง

## 4. กดซ้ำและการทำงานพร้อมกัน

- หาก membership ถอนแล้ว (`left_at IS NOT NULL`) ให้ยืนยันผลถอนเดิมสำเร็จโดยไม่เขียนซ้ำ ไม่เปลี่ยนเวลาถอน และไม่คืนที่ว่างเพิ่ม
- การยืนยันผลเดิมทำได้แม้กิจกรรมเริ่ม จบ หรือยกเลิกภายหลัง เพราะไม่ได้เป็นการถอนครั้งใหม่
- หากไม่เคยมี membership ให้ปฏิเสธ ไม่ตีความว่าเคยถอนสำเร็จ
- คำสั่งถอนพร้อมกันต้องทำให้เกิดการเปลี่ยน membership เพียงครั้งเดียว ใช้ transaction และล็อก Party ก่อน membership ตามลำดับร่วมกับการอนุมัติ แก้ไข และยกเลิก Party
- หากมีการอนุมัติสมาชิกใหม่ทันทีหลังถอน ที่ว่างที่แสดงภายหลังอาจถูกใช้แล้ว ต้องอ่านจำนวนจริง ไม่รับประกันว่าจะคงที่ว่างไว้ให้ใคร
- เมื่อถอนแล้วกลับเข้าร่วมและได้รับอนุมัติใหม่ การถอนครั้งถัดไปถือเป็นรอบใหม่ ต้องตรวจสิทธิ์และเวลาใหม่ การส่งซ้ำรับรองผลเดิมเฉพาะเมื่อ membership ยังมีสถานะถอนอยู่ ไม่ครอบคลุมคำสั่งเก่าที่มาถึงหลังกลับเข้าเป็นสมาชิกใหม่

## 5. ลำดับการพิจารณา

หลังตรวจการเข้าสู่ระบบและพบ Party ให้พิจารณาตามลำดับนี้ เพื่อให้กรณีทับซ้อนได้ผลตรงกัน:

1. ถ้าเป็น Host ให้ปฏิเสธการถอนทุกสถานะ
2. ถ้าไม่มี membership ของตนเอง ให้ปฏิเสธ
3. ถ้าถอนแล้ว ให้ยืนยันผลเดิมตามข้อ 4
4. ถ้า Party ยกเลิกแล้ว ให้ปฏิเสธการถอนครั้งแรก
5. ถ้าถึงหรือเลยเวลาเริ่ม ให้ปฏิเสธการถอนครั้งแรก
6. นอกเหนือจากนั้นให้ถอนและคืนที่ว่างครั้งเดียว เมื่อบันทึกล้มเหลวต้องไม่เหลือผลเปลี่ยนแปลงบางส่วน
